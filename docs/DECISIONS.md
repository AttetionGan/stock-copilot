| 约束 | 对设计的影响 |

## 当前工作方案

以下作为设计初稿的默认方案，后续依据原型与接入验证修订，不代表每个依赖和服务均已验证。

| 方案 | 原因 |
|---|---|
| 网页为主界面，适配电脑与手机 | 对应查看与配置需求，减少客户端维护 |
| mini 独立监控，Air 关闭不影响运行 | 与设备分工一致 |
| 微信通知先验证，PWA 后续增强 | 遵循手机偏好，控制第一版投入 |
| Python 单体、SQLite、独立后台任务 | 沿用初始设计，适合个人工具 |
| 手动/CSV 持仓先行 | 减少券商认证阻塞 |
| v0.1 只读，不包含交易执行与运行时 LLM | 保持原设计边界 |
| 先做模拟数据页面原型，再确定前端 | 避免仅根据框架方便程度决定手机体验 |

## 待验证，不阻塞文档和原型

- Streamlit 是否能满足手机核心流程、访问认证和提醒详情跳转。
- 用户是否接受所选微信推送服务的注册/实名条件；实际额度、模板与投递效果。
- mini 的系统版本、电源配置、联网与远程连接是否可用。
- 无额外手机 App 的外网访问方案、费用、认证方式和国内网络表现。
- 行情源的权限、价格时效、交易日历与允许的使用方式。
- 多币种、融资或空头持仓的处理边界；本版初稿仅按美元现金与多头资产设计。
