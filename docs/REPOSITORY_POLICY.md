# GitHub 上传边界

工程源代码可以公开；真实账户数据、个人投资记录和部署凭证保持私有。私有 GitHub 仓库也沿用此边界。

## 可以上传

| 内容 | 条件 |
|---|---|
| 业务代码、页面、测试、脚本 | 不含硬编码凭证、真实账户数据或个人连接参数 |
| README、产品设计、架构、路线图 | 面向项目本身，移除个人背景、聊天记录和实际交易计划 |
| 依赖清单、锁文件、CI 配置 | 不含嵌入式访问 token 或私有仓库凭证 |
| `.env.example`、部署模板 | 只含变量名、空值/占位符、通用路径 |
| 演示 CSV、测试样例 | 人工构造，存入 `examples/` 或 `tests/fixtures/`，注明模拟数据 |
| 产品截图与演示图 | 使用模拟数据生成，检查账户名、浏览器地址、通知、终端和图片元数据；放入 `docs/assets/` |

股票代码、公开接口名称和通用算法可以公开。真实关注列表、观察价格、成本与研究备注按个人投资数据处理；公开演示数值必须独立构造并标注。

## 不上传

- 券商 App Secret、Access Token、Refresh Token、推送 token、GitHub token、模型 API key。
- 密码、SSH/TLS 私钥、登录 cookie、浏览器登录状态、二维码、恢复码、Web Push 订阅信息。
- 真实持仓、现金、交易历史、账户报表、税务资料和个人观察规则。
- SQLite 数据库及其 journal/WAL/SHM 文件、备份、缓存、原始行情下载和第三方响应。
- 本机用户名、绝对个人路径、SSH 连接配置、内网拓扑和实际服务连接参数。
- 原始聊天、个人规划记录、真实运行日志、截图、录屏和调试导出。

来自券商或其他供应商的行情/研究文件，不能因可获取就认为允许公开分发。默认留在私有运行目录，演示与测试优先用人工构造数据。

## 存放约定

| 目录或文件 | 用途 | Git 默认处理 |
|---|---|---|
| `src/`、`tests/`、`docs/` | 代码、测试、通用文档 | 可提交，仍需内容审查 |
| `examples/*.csv`、`tests/fixtures/*.csv` | 人工构造的示例表格 | 可提交，禁止放真实数据 |
| `.env`、`*.local.*`、`*.private.*` | 本地配置与私密配置 | 忽略 |
| `.env.example` | 无秘密的配置模板 | 可提交 |
| `private/` | 私人笔记、规则、账户配置、原始文件 | 整个目录忽略 |
| `data/`、`exports/`、`backups/` | 数据库、行情、导出、备份 | 整个目录忽略 |
| `logs/`、`work/`、`screenshots/`、`recordings/` | 运行输出与调试材料 | 整个目录忽略 |
| `docs/assets/` | 经过检查的演示图片 | 可提交 |

其他位置的 CSV、TSV、Excel 文件默认忽略。JSON/YAML 是常见源码配置格式，不能仅靠后缀区分隐私；真实内容必须放入私密目录或使用明确的本地配置后缀。

## 上传前检查

1. 查看暂存文件列表及完整差异，逐项确认没有真实数据、路径或秘密；不把整个文件夹直接拖到网页上传。
2. 检查已经跟踪的文件是否命中新忽略规则；必要时仅移出 Git 跟踪，保留本地原件。
3. 首次推送或改变仓库可见性前，检查将上传的完整历史，包括旧配置、删除的文件和演示附件；运行秘密扫描并人工检查。
4. 图片、压缩包、Notebook 输出、CI 日志、Release 附件和 Issue/PR 内容同样检查；它们可能绕过源码忽略规则。
5. 检查第三方代码和素材许可；对外发布前确定项目 LICENSE，不能把未选定许可证称为已经完成开源发布。

`.gitignore` 是误提交防护，不是加密或访问控制；它不清理历史，不保护已跟踪的文件，也不阻止强制添加、手工压缩或直接上传。

如果秘密已进入远端，先撤销/轮换秘密，再处理历史和副本；仅删除当前文件不算解决。真实隐私数据泄露也不能通过改成私有仓库就认定已经消除。
