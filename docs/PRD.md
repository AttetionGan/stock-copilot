# Stock Copilot v0.1 产品设计

设计基线：2026-10-17；界面约定更新：2026-10-18。状态：**产品设计完成，作为 v0.1 开发基线；功能与部署验收尚未完成。**

本基线已确认四个核心模块、页面流程、范围边界和 12 项验收标准，并补齐行情有效性、CSV 快照覆盖、通知重试与过期约定。现阶段可进入实现；行情源阈值、通知服务和外网接入等需实测的参数，在对应开发阶段验证并记录，不影响产品设计完成状态。后续如调整功能范围或用户行为，应同步更新本文及受影响的架构、路线图和决策记录。

本版沿用初始设计的四个核心模块，纳入后续明确的手机网页、微信通知和双机部署要求。本文是功能范围与验收依据；技术实现见 [架构方案](ARCHITECTURE.md)，开发顺序见 [路线图](ROADMAP.md)。

## 1. 产品目标

让用户每天能回答三个问题：关注的资产发生了什么变化；自己的仓位和现金是什么状态；哪些用户设定的观察条件已经触发。

定位为 Personal AI Investment Copilot 的第一阶段：Portfolio & Market Monitor。第一版面向单个用户，不建设多用户平台，不做短线交易终端。

呈现形式为适配电脑和 iPhone 的网页。手机优先使用微信和浏览器；PWA 作为后续增强。Mac mini 提供持续监控能力，MacBook Air 用于开发。

## 2. v0.1 功能模块总表

**v0.1 = 行情观察 + 持仓管理 + 价格提醒 + 投资面板。** 投资研究背景以手动备注保留；自动财报分析、新闻分析和 AI 决策建议属于后续能力。

| 模块 | v0.1 必须支持 | 本版不承诺 | 验收对应 |
|---|---|---|---|
| MKT 行情观察（Market Watchlist） | 自定义关注列表、报价/涨跌幅/来源/时间、近期走势、观察区间和提醒状态、手动研究备注 | 自动选股、实时逐笔行情、技术指标平台 | AC-01、AC-11、AC-12 |
| PTF 持仓管理（Portfolio Tracker） | 手动录入、CSV 导入、多账户分组与汇总、数量/成本/市值/未实现盈亏/仓位占比、美元现金 | 自动券商同步、交易流水分析、自动对账、账户日收益 | AC-03 |
| ALT 价格提醒（Price Alert Engine） | 自定义多个价格区间、启停规则、去重与冷却、事件历史、微信通知和查看状态 | 自动买卖信号、自动交易、秒级触发保证 | AC-02、AC-05 |
| DSH 投资面板（Investment Dashboard） | 汇总资产与现金、关注列表、持仓分布、最近提醒、股票详情、适配 Mac 与 iPhone | 原生 App、PWA 推送、复杂绩效归因 | AC-04、AC-06 |

后台调度、健康状态、访问控制、数据备份和 GitHub 隐私边界是这四个模块的共同交付条件，不另扩展成独立产品模块。

### 2.1 MKT：行情观察

| 编号 | 功能 | 支持范围 |
|---|---|---|
| MKT-01 | 关注列表管理 | 添加、删除、查看、启用/停用标的；校验重复项与无效代码，重启后保留配置 |
| MKT-02 | 报价摘要 | 显示股票代码、中文名、币种、最新取得的报价、相对前一交易日收盘价的涨跌额/幅；英文名在详情保留，缺少基准价格时标记缺失 |
| MKT-03 | 数据可信度 | 同时展示来源、行情时间、采集时间、交易时段及正常/延迟/过期/不可用状态；不能把采集时间当行情时间 |
| MKT-04 | 近期走势 | 初稿范围为最近 30 个交易日的日收盘价折线；标明价格口径、日期与来源，不提供分钟线或技术指标；不足 30 日展示实际可用数据 |
| MKT-05 | 观察状态 | 总览、关注、持仓的股票卡片统一展示观察区间名称、美元上下界与区间内/区间外/停用状态；未配置时明确提示；同一标的可关联多条规则 |
| MKT-06 | 研究背景 | 手动维护关注理由、投资期限、风险备注、最近复核日期，与股票详情及规则关联 |

可提供 QQQM、MU、NVDA、GOOGL、TSLA 等公开标的的演示配置，不能硬编码为不可修改的列表，也不把它当作真实持仓或投资建议。

至少验证一个真实行情源。沿用统一 MarketDataProvider 的设计，开发阶段先用模拟数据，可优先验证 yfinance，再评估 Longbridge；实际权限、延迟和稳定性以接入验证为准。行情接入与券商持仓同步分开，不需要先连接真实券商账户才能使用关注列表。

### 2.2 PTF：持仓管理

| 编号 | 功能 | 支持范围 |
|---|---|---|
| PTF-01 | 账户管理 | 使用券商标签与账户别名区分账户；可标注 Longbridge、IBKR 或手工账户，不要求填写真实账号 |
| PTF-02 | 手动维护 | 添加、编辑、移除持仓，维护数量、平均成本、美元现金；破坏性修改需确认 |
| PTF-03 | CSV 导入 | 导入持仓和现金快照，预览字段、错误行与替换范围，确认后原子写入；有错误时不部分覆盖正式数据 |
| PTF-04 | 估值与盈亏 | 计算成本、市值、未实现盈亏和未实现盈亏比例；平均成本为零时盈亏比例显示不可计算。资产金额支持 USD/CNY 展示切换，折算口径见第 6 节 |
| PTF-05 | 仓位展示 | 按账户查看，也可跨账户按股票汇总数量、成本与市值；以环形饼图展示分布，可切换股票持仓占比及含现金总资产占比 |
| PTF-06 | 现金与时间 | 展示各账户现金和汇总现金，明确快照更新时间与手动/CSV 来源；不宣称与券商实时一致 |

范围限定为美元计价美股/ETF 多头持仓、非负美元现金；允许小数股。负数量、负现金、其他币种、期权和融资头寸不进入本版计算，导入时明确拒绝，不静默转换。

上述限制针对原始录入与账本币种；人民币仅作为美元资产的折算展示单位，不代表支持录入人民币现金或人民币计价持仓。

保持 Broker Adapter 的统一持仓结构，以便以后接入券商。Longbridge/IBKR API 自动同步可做小规模探索，但不属于 v0.1 支持承诺，不影响本版发布验收。

持仓环形图随账户筛选更新，默认按股票市值计算、不含现金；切换至“含现金总资产”时将现金单独作为一个扇区。相同股票跨账户合并，扇区标明标的与占比，悬停或点触可查看金额。任一纳入范围的持仓缺少有效报价时，暂停绘图并提示估值不完整，不把已知部分重新归一化为全部仓位；没有正值资产时显示空状态。

### 2.3 ALT：价格提醒

| 编号 | 功能 | 支持范围 |
|---|---|---|
| ALT-01 | 规则配置 | 同一股票可创建多个命名观察区间；配置用途（买入观察／卖出观察／观察）、上下界、启用/停用、冷却时间；上界不得低于下界。用途为用户标注，不改变区间判断逻辑 |
| ALT-02 | 定时判断 | 仅用有效报价按区间判断，正常交易时段约每 5 分钟检查；具体状态规则见第 5 节 |
| ALT-03 | 去重与恢复 | 持续命中不重复生成事件；离开重入、冷却和服务重启后行为一致 |
| ALT-04 | 提醒历史 | 保存规则名称/用途/区间快照、标的、触发报价、行情时间、触发时间和来源；修改或删除规则不改写旧事件；旧事件缺少用途时显示“观察” |
| ALT-05 | 手机通知 | 优先微信渠道；通知含事件摘要与详情入口，独立记录发送尝试和失败；不以 mini 本地通知替代手机验收 |
| ALT-06 | 人工查看 | 支持未查看/已查看筛选和标记；已查看仅表示阅读，不代表交易或接受投资建议 |

多个区间独立判断，允许重叠；同一轮命中多条规则分别留事件，可合并成一条手机通知并列明各规则。第一版只支持进入有限价格区间，不额外承诺涨跌幅、新闻、组合风险或复杂条件表达式。

### 2.4 DSH：投资面板

| 编号 | 功能 | 支持范围 |
|---|---|---|
| DSH-01 | 总览 | 首区块标题为“以下股票已到重点观察区间”，不再叠加“投资总览”大标题；显示未查看数量、标的及中文名、用途、触发价与区间，支持详情和标记已查看；其后展示股票市值、账户现金、含现金总资产、未实现盈亏及数据健康状态；以带当前金额的关系图展示市值＋现金＝总资产、市值－成本＝未实现盈亏 |
| DSH-02 | 统一导航 | 总览、关注、持仓、提醒、设置五个入口；提醒与股票详情能相互跳转 |
| DSH-03 | 股票详情 | 汇集报价、走势、观察区间、跨账户相关持仓、研究背景和历史提醒 |
| DSH-04 | 电脑与手机 | 同一套数据，电脑适合详细表格，手机优先摘要与卡片；核心操作可在 iPhone 完成。设置页可选“浅色模式／深色模式／跟随系统”，默认跟随系统，手动选择覆盖系统偏好；卡片、控件、导航和图表同步适配，各设备独立，不由部署机器决定 |
| DSH-05 | 设置与状态 | 显示时区、通知配置状态、服务最近成功时间；提供刷新网页数据操作，但不绕过后台规则去重 |

总览中的现金是用户维护的余额，不等同于购买力、可提款金额。原始界面草图中的 Daily P&L 不纳入本版，避免在缺少交易、资金流和历史快照时生成误导指标。

总览与“持仓与现金”共用一张整合资产卡，替代四张独立指标卡和额外的计算关系面板：在原资产概览位置，单行展示“总资产＝现金＋股票市值”，并在股票市值分组内拆分成本与未实现盈亏，各项金额不重复展示；窄屏支持卡内横向滑动。资产卡使用同一份计算结果，持仓页随账户筛选更新，不独立估算。持仓成本为录入数量与平均成本的合计；未实现盈亏已包含在市值中，计算总资产不再次相加。缺少有效报价时，相关操作数与结果显示“待补全”，已知现金和成本仍正常显示；亏损按负值展示。

价格与盈亏统一视觉层级：股价、总资产使用大号加粗数字，市值与未实现盈亏分组展示；涨跌与盈亏可在设置页选择绿涨红跌／红涨绿跌，默认绿涨红跌，并同时保留文字、正负号，零值使用中性色。报价涨跌金额/百分比相对前收盘，持仓收益率相对持仓成本，两者明确标注，不称为账户日收益。观察区间上下界、提醒触发报价及相关持仓沿用统一数字样式；金额保留币种、千分位和两位小数。过期报价以“过期参考价”中性显示，暂停涨跌判断；缺失报价和不可计算的估值显示“待补全”，不使用盈利/亏损色。浅色与深色主题均适用。

默认采用紧凑布局，以减少查看全局所需的滚动：缩减页头、卡片内边距和重复说明；总览先展示高对比度的待查看区间提醒区域，突出未查看数量，最多展示前三条并提供全部提醒入口；没有未查看事件时显示空状态，其后展示资产摘要与关注列表。桌面总览采用三列股票摘要，五个演示标的按两行组织；价格、涨跌额/幅和全部观察区间直接可见，使用卡头入口进入详情。关注页作为管理入口，展示标的、区间值/状态、区间启用数与关注理由填写状态，支持按已配/未配区间筛选、添加、确认移除和进入配置，不重复整套行情卡片。桌面持仓明细与分布图并排，每条持仓合并标的/数量、报价、市值、盈亏、成本、占比和观察区间。手机按可用宽度重排，优先明细；详情页的区间编辑和研究备注默认折叠，重要数据异常不折叠。目标是在常用桌面尺寸尽量一屏或少量滚动掌握五个演示标的与资产概况；实际效果须通过浏览器视觉验收，不以页面自动检查替代。

界面配色统一为雾白/深蓝灰底色、靛蓝操作与总资产强调色；绿/红表示涨跌和盈亏，区间命中使用主色并保留状态文字，避免与盈亏混淆。三种外观模式与两种涨跌配色在当前会话跨页保留，重置演示数据保留这两项选择。待查看提醒使用独立的琥珀色强调，不随涨跌配色改变。外观、涨跌配色、资产币种与演示控制统一放在独立设置页，不占用业务页首屏；电脑侧栏和手机底部导航均提供设置入口，修改立即应用于当前会话的各页面。

总览提醒区仅保留一个标题、紧凑的“条待查看”数量和全部提醒入口，去除巨大独立数字及重复说明。未查看事件保留触发时间，不宣称历史触发价仍是当前价格；没有未查看事件时标题为“重点观察区间”并显示已全部查看的空状态。手机标题独占首行，内容与操作按钮自然换行。代码旁显示中文简称，不增加卡片列数；提醒、关注、持仓、详情、添加选项和图表保持同一名称。中文名是展示别名，关联与计算始终使用标的代码，缺失名称时回退代码。

## 3. 完整使用流程

1. 在网页添加关注标的并配置观察区间。
2. 手动录入或导入持仓与现金，查看导入预览后确认。
3. Mac mini 定时获取行情，检查交易时段和数据有效性。
4. 发现新的触发事件，保存记录并尝试发送通知。
5. 用户在手机上看到简短提醒，打开网页查看详情。
6. 用户将提醒标记为已查看；这不代表买入、卖出或交易完成。

## 4. 页面设计

电脑采用侧边导航；手机采用底部导航。统一五个入口：总览、关注、持仓、提醒、设置。设置单独成页，不在每页顶部重复展示。

| 页面 | 首屏内容 | 用户操作 | 手机适配 |
|---|---|---|---|
| 总览 | 待查看区间提醒、数据健康状态、账户概览、行情摘要 | 进入股票或提醒详情、标记已查看、查看全部提醒 | 提醒优先，其后资产与行情摘要；异常状态保持可见 |
| 关注 | 标的、观察区间/启用数、关注理由填写状态 | 添加、确认移除、筛选已配/未配区间、进入规则与研究配置 | 管理清单，与总览行情摘要区分 |
| 持仓 | 按账户分组的现金、成本、市值、未实现盈亏、占比、每只股票的观察区间数值 | 手动编辑、导入 CSV、查看导入结果 | 摘要优先，单个持仓展开详情 |
| 提醒 | 未查看/历史事件、触发原因、发送状态 | 标记已查看、打开股票详情 | 按时间排列，支持直接进入单条详情 |
| 设置 | 外观、涨跌配色、资产币种；通知与运行状态在对应接入阶段补齐 | 修改显示偏好；M1 的演示控制放在折叠区 | 底部导航直接进入，不在各业务页占用顶部空间 |

股票详情包含：报价及时间、近期价格走势、配置区间、相关持仓、研究备注、历史提醒。走势缺失时显示缺失状态，不影响报价和规则查看。

观察区间使用同一份规则数据；在股票详情修改后，总览、关注和持仓同步显示最新上下界，无须分别维护。多条区间逐条列出，停用规则仍展示数值并标注“已停用”；行情无效时保留区间数值，状态显示暂停判断。没有配置的标的不自动生成观察价格。

设置包括：通知渠道连接状态、正常交易时段说明、显示时区、服务最近成功运行时间。本版不提供尚未支持的盘前/盘后时段开关。第一版凭证在部署环境配置，网页不回显凭证。

## 5. 提醒行为与通知体验

默认仅监控美股正常交易时段，约每 5 分钟检查一次；扩展交易时段明确列为后续范围。根据交易日历和美东时区处理节假日、提前收市与夏令时。

“进入区间”指采样时观察到满足条件。两次检查之间短暂进入又离开的价格变化可能不会被捕获，不能对外承诺即时触发。盘前、盘后或其他时段的报价即使收到，也明确标记且不用于本版正常时段规则。

### 5.1 行情有效性与过期判定

- 每个行情源必须明确标注是否延迟、预期延迟及用于提醒的最大报价年龄。具体阈值在接入验证后配置并记录；未配置或未验证前，该行情源只用于展示，不启用价格提醒。
- 报价年龄按检查时刻与行情自身时间之差计算，不使用采集时间或页面刷新时间替代。超过最大报价年龄即标记过期；重新请求或刷新页面不能改变旧报价的有效性。
- 行情时间缺失、无法解析或晚于检查时刻时，标记不可用于判断，不触发提醒。数据源声明的延迟不能自动成为放宽阈值的理由。
- 过期报价可作为历史参考展示，但必须突出标注行情时间与过期状态；持仓估值不得将其计入完整、有效的资产总额。有效报价恢复后继续判断，数据中断本身不视为离开区间。

### 5.2 规则与提醒内容

通知内容示例，均为模拟数据：

> MU 进入观察区间 A。报价 205 USD，区间 200–210 USD。附行情时间与查看详情入口。请结合自己的研究记录重新评估。

通知不包含账户标识、持仓数量或资产总额。完整信息在登录后查看。第三方通知模板是否支持直接跳转，需在接入验证中确认；不支持时提供网页入口作为替代。

规则行为：

- 区间上下界均包含在触发范围内。
- 同一区间持续命中只产生一次事件。
- 首次启用或修改规则时，若有效报价已经在区间内，产生一次“启用时已满足”事件。
- 离开后再次进入才允许生成新的事件；建议默认冷却 60 分钟，可在使用验证后调整。
- 冷却期间的重入记录为被抑制的状态变化，不在冷却结束时补发旧事件。
- 停用规则后停止生成新事件；重新启用或修改价格条件按新的规则版本检查。单纯刷新网页不触发规则重置。
- 数据缺失、过期或时段不符时不触发，也不把状态重置为区间外。
- 删除关注项先展示关联规则，确认后停用规则；历史事件保留标的快照。

“未查看/已查看”与“待发送/服务已接受/失败/已过期”分开记录。没有送达回执时，不展示“已送达手机”。

### 5.3 通知失败、重试与过期

- 默认最多尝试发送 3 次，包含首次发送；对可重试的网络或服务异常，分别在首次失败后约 1 分钟、5 分钟重试。认证失败、配置错误等不可重试错误直接记录失败，不反复请求。
- 默认有效期为事件触发后 15 分钟，截止时间随事件持久化，重试或服务重启不延长有效期。这是通知投递期限，不会延长第 5.1 节的行情有效性。
- 每次发送前检查有效期；超过截止时间或已达最大尝试次数时停止自动发送。网络恢复后仅处理仍有效且可重试的记录，不集中补发过时价格提醒。
- 因过期停止的记录标记“已过期”，因重试耗尽或不可重试错误停止的记录标记“失败”，均保留事件、尝试次数与脱敏原因，供用户在网页查看。
- 同一事件复用同一发送记录，不为每次重试创建新的价格事件。服务已接受请求后不主动重复发送；若渠道不支持幂等或回执，网络超时仍可能造成重复通知，界面不宣称恰好送达一次。

## 6. 持仓与数据口径

第一版限定美元计价的美股/ETF 多头持仓和非负美元现金。多个券商账户可分别录入，再汇总；其他币种先明确提示不支持，不能直接相加。

设置页提供“资产显示币种”切换 USD 美元／CNY 人民币，当前会话内跨页面保持一致。总览和持仓资产卡的总资产、现金、市值、总成本、未实现盈亏，持仓明细及股票详情相关持仓的金额，以及环形图中心总额和提示金额同步切换。仓位占比和相对成本收益率不变；股票报价、平均成本/股、走势图、观察区间与历史提醒触发价保持 USD，并明确标注。

折算仅在展示层进行，不修改美元底账或规则；使用同一份 USD/CNY 汇率换算资产与盈亏，不计算汇兑损益或按历史汇率重建人民币收益。使用 Decimal 先计算和换算，再四舍五入展示两位小数，分项可能有末位舍入尾差；缺失估值保持未知。

M1 使用固定示例 `1 USD = 7.20 CNY`，界面必须标明“演示、非实时”。正式行情接入时需验证汇率来源与时间，并显示折算依据；未取得有效汇率时人民币金额显示待补全，可返回 USD，不将演示汇率用于真实资产。自动汇率同步仍为后续能力。

- 持仓字段：券商标签、账户别名、股票代码、数量、平均成本、币种、快照时间与录入来源。
- 现金字段：账户别名、币种、现金余额；不当作券商购买力或可提款金额。
- 导入以账户持仓快照为单位，预览替换范围并确认，不累计追加，避免重复导入翻倍。
- 持仓成本＝数量×平均成本；市值＝数量×有效报价；未实现盈亏＝市值－成本。
- 跨账户同一标的的平均成本＝合计成本÷合计数量；数量为零不参与计算。未实现盈亏比例＝未实现盈亏÷成本，成本为零则不可计算。
- 股票市值合计＋美元现金合计＝含现金总资产；计算使用 Decimal，并明确显示精度。
- 占比同时标注分母：股票持仓占比，或含现金总资产占比。
- 缺少报价时总资产标记“不完整”，不能静默按零估值；历史报价可展示但必须标注过期。
- 不提供已实现收益、税费归因、完整收益率曲线或账户日盈亏。标的日涨跌幅不等于账户日收益。
- 拆股、分红和成本变化由用户通过更新快照维护，v0.1 不自动重建交易账本。

### 6.1 CSV 快照覆盖与异常处理

- 持仓与现金作为两个独立的导入范围，分别预览、分别确认；预览按账户列出将新增、修改和移除的内容。可以在一次操作中确认多个范围，但所有已确认范围必须通过校验后才一起原子写入。
- 持仓快照只替换明确选定账户的持仓，不修改该账户现金，也不影响未选定账户。只导入现金同样不得修改持仓。
- 现金字段或现金文件未提供时保留原余额，不按零覆盖；将余额改为零必须在现金预览中明确显示并确认。
- 同一批持仓快照内，规范化后的“账户别名＋股票代码”必须唯一；出现重复行时整批拒绝并指出行号，不自动相加，也不采用最后一行覆盖。需要合并的多笔交易应先转换为单条持仓快照。
- 空文件或仅有表头的 CSV 拒绝导入，不把它当作清空指令。确需清空某账户持仓时，使用显式的“清空该账户持仓”操作并二次确认；现金与其他账户保持不变。
- 任一已确认范围存在错误时，本次导入不写入任何更改；成功导入后展示影响范围、更新时间与结果摘要。重复导入同一快照不会累计增加持仓或现金。

## 7. 投资研究与 AI 能力边界

保留初始设计的 Investment Decision Context，作为关注模块内的手动信息，而非新增自动研究模块。

| 信息 | v0.1 支持方式 |
|---|---|
| 关注理由 / Investment Thesis | 用户编辑的文本，不由系统自动生成 |
| 投资期限 / Time Horizon | 用户填写的文本或日期说明 |
| 观察区间 / Watch Zone | 引用已配置的价格规则，不维护另一套重复阈值 |
| 风险备注 / Risk Notes | 用户维护风险与待核实事项 |
| 最近复核 / Last Reviewed | 用户明确执行复核动作时记录；不以行情刷新时间代替 |

这些信息随标的持久化，可从股票详情和提醒详情查看；字段可留空，不妨碍基础监控。真实备注、观察区间和持仓均属于私密运行数据。

v0.1 不调用在线 LLM、不自动总结财报或新闻、不生成买卖建议、不实现多 Agent 研究或订单草稿。保留独立的数据模型与服务接口，便于后续 AI Research 读取有来源和时间的上下文；仅保留扩展边界，不开发空壳 Agent 平台。

| v0.1 必须完成 | 后续考虑 |

| 设计项 | 本版口径 |

| 账户日盈亏与复杂现金指标 | 暂不支持；展示未实现盈亏与录入现金余额 |
| 盘前/盘后/夜盘 | 数据模型区分时段，本版提醒只覆盖正常交易时段 |
| 投资研究背景 | 保留手动字段与本地存储，AI 自动分析后置 |

## 9. 共同交付要求

- mini 后台任务独立于网页运行；Air 合盖后监控继续，任务互斥、状态持久化、失败有记录且有限重试。
- 报价过期、缺失或服务异常在网页显式展示；数据错误不得产生价格提醒。
- 手机在外网通过 HTTPS 和访问认证查看详情；未登录无法读取账户、规则或事件。
- 数据有一致性备份和恢复验证。mini 断电或整机断网时无法自发通知，不承诺永不中断。
- 代码、通用文档、模拟样例可上传 GitHub；真实数据、凭证、日志与私密研究背景遵循 [上传边界](REPOSITORY_POLICY.md)。

## 10. 验收标准

| 编号 | 通过条件 |
|---|---|
| AC-01 | 可增删、启停关注标的，报价/涨跌幅标明基准、来源和时间；真实源可获取演示列表标的报价；验证报价年龄的阈值边界，过期、时间无效、阈值未验证或非正常时段数据不触发提醒，刷新页面不能使旧报价重新有效 |
| AC-02 | 同一股票多个区间分别工作；边界、重叠、持续命中、离开重入、首次启用、冷却、启停和重启后的规则行为符合定义；旧事件保留规则快照 |
| AC-03 | 手动维护和 CSV 导入均可用；持仓与现金分别预览确认，持仓导入不覆盖现金或其他账户；重复行、空 CSV、无效行和不支持的币种/头寸阻止整批写入；重复导入不累计余额；显式清空需二次确认；多账户汇总、加权成本、盈亏、现金和仓位占比以已知样例核对 |
| AC-04 | Mac 与 iPhone 可完成查看、配置区间、查看单条提醒；核心操作无需横向拖动大表格 |
| AC-05 | 真机收到测试通知；记录渠道结果；点击后能查看对应事件或明确的替代入口；验证最多 3 次尝试、不可重试错误、15 分钟有效期及重启不延长期限，断网恢复不补发过期提醒，失败与过期记录可在网页查看 |
| AC-06 | 用户在蜂窝网络下可通过登录保护访问页面；未登录无法读取持仓和事件详情 |
| AC-07 | Air 合盖后，mini 完成一个完整美股正常交易时段的监控；日志可核验采集与提醒状态 |
| AC-08 | 服务重启后恢复；任务不重叠；断网、过期行情和通知失败有明确状态与有限重试 |
| AC-09 | 无交易执行接口；仓库、样例和日志检查未暴露真实账户数据或凭证 |
| AC-10 | 至少完成一次数据备份恢复演练，恢复后能读取持仓、规则和历史事件 |
| AC-11 | 股票详情展示近期日收盘价走势及来源、价格口径；不足 30 个交易日或数据缺失有明确提示，报价和规则仍独立可用 |
| AC-12 | 手动研究字段可编辑、保存、重启后读取；提醒详情可访问该标的背景，最近复核日期不被行情刷新覆盖；不发生运行时 LLM 调用 |

以上均为待完成标准，目前没有通过记录。
