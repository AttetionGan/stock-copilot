# Stock Copilot v0.1 产品设计

日期：2026-10-17。状态：v0.1 功能范围整理稿；尚未实现或完成验收。

本版沿用初始设计的四个核心模块，纳入后续明确的手机网页、微信通知和双机部署要求。本文是功能范围与验收依据；技术实现见 [架构方案](ARCHITECTURE.md)，开发顺序见 [路线图](ROADMAP.md)。

## 1. 产品目标

让用户每天能回答三个问题：关注的资产发生了什么变化；自己的仓位和现金是什么状态；哪些用户设定的观察条件已经触发。

定位为 Personal AI Investment Copilot 的第一阶段：Portfolio & Market Monitor。第一版面向单个用户，不建设多用户平台，不做短线交易终端。

呈现形式为适配电脑和 iPhone 的网页。手机优先使用微信和浏览器；PWA 作为后续增强。Mac mini 提供持续监控能力，MacBook Air 用于开发。

## 2. v0.1 功能模块总表

**v0.1 = 行情观察 + 持仓管理 + 价格提醒 + 投资面板。** 投资研究背景以手动备注保留；自动财报分析、新闻分析和 AI 决策建议属于后续能力。

| 模块 | v0.1 必须支持 | 本版不承诺 | 验收对应 |
|---|---|---|---|
| MKT 行情观察（Market Watchlist） | 自定义关注列表、报价/涨跌幅/来源/时间、近期走势、观察区间和提醒状态、手动研究备注 | 自动选股、实时逐笔行情、技术指标平台 | AC-01、AC-11、AC-12 |
| PTF 持仓管理（Portfolio Tracker） | 手动录入、CSV 导入、多账户分组与汇总、数量/成本/市值/未实现盈亏/仓位占比、美元现金 | 自动券商同步、交易流水分析、自动对账、账户日收益 | AC-03 |
| ALT 价格提醒（Price Alert Engine） | 自定义多个价格区间、启停规则、去重与冷却、事件历史、微信通知和查看状态 | 自动买卖信号、自动交易、秒级触发保证 | AC-02、AC-05 |
| DSH 投资面板（Investment Dashboard） | 汇总资产与现金、关注列表、持仓分布、最近提醒、股票详情、适配 Mac 与 iPhone | 原生 App、PWA 推送、复杂绩效归因 | AC-04、AC-06 |

后台调度、健康状态、访问控制、数据备份和 GitHub 隐私边界是这四个模块的共同交付条件，不另扩展成独立产品模块。

### 2.1 MKT：行情观察

| 编号 | 功能 | 支持范围 |
|---|---|---|
| MKT-01 | 关注列表管理 | 添加、删除、查看、启用/停用标的；校验重复项与无效代码，重启后保留配置 |
| MKT-02 | 报价摘要 | 显示股票代码、名称、币种、最新取得的报价、相对前一交易日收盘价的涨跌额/幅；缺少基准价格时标记缺失 |
| MKT-03 | 数据可信度 | 同时展示来源、行情时间、采集时间、交易时段及正常/延迟/过期/不可用状态；不能把采集时间当行情时间 |
| MKT-04 | 近期走势 | 初稿范围为最近 30 个交易日的日收盘价折线；标明价格口径、日期与来源，不提供分钟线或技术指标；不足 30 日展示实际可用数据 |
| MKT-05 | 观察状态 | 展示启用的观察区间、是否处于区间内、最近提醒；同一标的可关联多条规则 |
| MKT-06 | 研究背景 | 手动维护关注理由、投资期限、风险备注、最近复核日期，与股票详情及规则关联 |

可提供 QQQM、MU、NVDA、GOOGL、TSLA 等公开标的的演示配置，不能硬编码为不可修改的列表，也不把它当作真实持仓或投资建议。

至少验证一个真实行情源。沿用统一 MarketDataProvider 的设计，开发阶段先用模拟数据，可优先验证 yfinance，再评估 Longbridge；实际权限、延迟和稳定性以接入验证为准。行情接入与券商持仓同步分开，不需要先连接真实券商账户才能使用关注列表。

### 2.2 PTF：持仓管理

| 编号 | 功能 | 支持范围 |
|---|---|---|
| PTF-01 | 账户管理 | 使用券商标签与账户别名区分账户；可标注 Longbridge、IBKR 或手工账户，不要求填写真实账号 |
| PTF-02 | 手动维护 | 添加、编辑、移除持仓，维护数量、平均成本、美元现金；破坏性修改需确认 |
| PTF-03 | CSV 导入 | 导入持仓和现金快照，预览字段、错误行与替换范围，确认后原子写入；有错误时不部分覆盖正式数据 |
| PTF-04 | 估值与盈亏 | 计算成本、市值、未实现盈亏和未实现盈亏比例；平均成本为零时盈亏比例显示不可计算 |
| PTF-05 | 仓位展示 | 按账户查看，也可跨账户按股票汇总数量、成本与市值；展示股票持仓占比及含现金总资产占比 |
| PTF-06 | 现金与时间 | 展示各账户现金和汇总现金，明确快照更新时间与手动/CSV 来源；不宣称与券商实时一致 |

范围限定为美元计价美股/ETF 多头持仓、非负美元现金；允许小数股。负数量、负现金、其他币种、期权和融资头寸不进入本版计算，导入时明确拒绝，不静默转换。

保持 Broker Adapter 的统一持仓结构，以便以后接入券商。Longbridge/IBKR API 自动同步可做小规模探索，但不属于 v0.1 支持承诺，不影响本版发布验收。

### 2.3 ALT：价格提醒

| 编号 | 功能 | 支持范围 |
|---|---|---|
| ALT-01 | 规则配置 | 同一股票可创建多个命名观察区间；配置上下界、启用/停用、冷却时间；上界不得低于下界 |
| ALT-02 | 定时判断 | 仅用有效报价按区间判断，正常交易时段约每 5 分钟检查；具体状态规则见第 5 节 |
| ALT-03 | 去重与恢复 | 持续命中不重复生成事件；离开重入、冷却和服务重启后行为一致 |
| ALT-04 | 提醒历史 | 保存规则名称/区间快照、标的、触发报价、行情时间、触发时间和来源；修改或删除规则不改写旧事件 |
| ALT-05 | 手机通知 | 优先微信渠道；通知含事件摘要与详情入口，独立记录发送尝试和失败；不以 mini 本地通知替代手机验收 |
| ALT-06 | 人工查看 | 支持未查看/已查看筛选和标记；已查看仅表示阅读，不代表交易或接受投资建议 |

多个区间独立判断，允许重叠；同一轮命中多条规则分别留事件，可合并成一条手机通知并列明各规则。第一版只支持进入有限价格区间，不额外承诺涨跌幅、新闻、组合风险或复杂条件表达式。

### 2.4 DSH：投资面板

| 编号 | 功能 | 支持范围 |
|---|---|---|
| DSH-01 | 总览 | 展示股票市值、账户现金、含现金总资产、未实现盈亏、未查看提醒数及数据健康状态 |
| DSH-02 | 统一导航 | 总览、关注、持仓、提醒四个入口；提醒与股票详情能相互跳转 |
| DSH-03 | 股票详情 | 汇集报价、走势、观察区间、跨账户相关持仓、研究背景和历史提醒 |
| DSH-04 | 电脑与手机 | 同一套数据，电脑适合详细表格，手机优先摘要与卡片；核心操作可在 iPhone 完成 |
| DSH-05 | 设置与状态 | 显示时区、通知配置状态、服务最近成功时间；提供刷新网页数据操作，但不绕过后台规则去重 |

总览中的现金是用户维护的余额，不等同于购买力、可提款金额。原始界面草图中的 Daily P&L 不纳入本版，避免在缺少交易、资金流和历史快照时生成误导指标。

## 3. 完整使用流程

1. 在网页添加关注标的并配置观察区间。
2. 手动录入或导入持仓与现金，查看导入预览后确认。
3. Mac mini 定时获取行情，检查交易时段和数据有效性。
4. 发现新的触发事件，保存记录并尝试发送通知。
5. 用户在手机上看到简短提醒，打开网页查看详情。
6. 用户将提醒标记为已查看；这不代表买入、卖出或交易完成。

## 4. 页面设计

电脑采用侧边导航；手机采用底部导航。初稿统一四个入口：总览、关注、持仓、提醒。设置入口放在页面右上角。

| 页面 | 首屏内容 | 用户操作 | 手机适配 |
|---|---|---|---|
| 总览 | 数据健康状态、未查看提醒、账户概览、关注摘要 | 进入股票或提醒详情 | 先提醒与数据状态，再资产摘要 |
| 关注 | 标的、报价、涨跌幅、行情时间、观察区间 | 增删标的、配置规则、编辑研究备注 | 使用卡片，减少横向滚动 |
| 持仓 | 按账户分组的现金、成本、市值、未实现盈亏、占比 | 手动编辑、导入 CSV、查看导入结果 | 摘要优先，单个持仓展开详情 |
| 提醒 | 未查看/历史事件、触发原因、发送状态 | 标记已查看、打开股票详情 | 按时间排列，支持直接进入单条详情 |

股票详情包含：报价及时间、近期价格走势、配置区间、相关持仓、研究备注、历史提醒。走势缺失时显示缺失状态，不影响报价和规则查看。

设置包括：通知渠道连接状态、正常交易时段说明、显示时区、服务最近成功运行时间。本版不提供尚未支持的盘前/盘后时段开关。第一版凭证在部署环境配置，网页不回显凭证。

## 5. 提醒行为与通知体验

默认仅监控美股正常交易时段，约每 5 分钟检查一次；扩展交易时段明确列为后续范围。根据交易日历和美东时区处理节假日、提前收市与夏令时。

“进入区间”指采样时观察到满足条件。两次检查之间短暂进入又离开的价格变化可能不会被捕获，不能对外承诺即时触发。盘前、盘后或其他时段的报价即使收到，也明确标记且不用于本版正常时段规则。

通知内容示例，均为模拟数据：

> MU 进入观察区间 A。报价 205 USD，区间 200–210 USD。附行情时间与查看详情入口。请结合自己的研究记录重新评估。

通知不包含账户标识、持仓数量或资产总额。完整信息在登录后查看。第三方通知模板是否支持直接跳转，需在接入验证中确认；不支持时提供网页入口作为替代。

规则行为：

- 区间上下界均包含在触发范围内。
- 同一区间持续命中只产生一次事件。
- 首次启用或修改规则时，若有效报价已经在区间内，产生一次“启用时已满足”事件。
- 离开后再次进入才允许生成新的事件；建议默认冷却 60 分钟，可在使用验证后调整。
- 冷却期间的重入记录为被抑制的状态变化，不在冷却结束时补发旧事件。
- 停用规则后停止生成新事件；重新启用或修改价格条件按新的规则版本检查。单纯刷新网页不触发规则重置。
- 数据缺失、过期或时段不符时不触发，也不把状态重置为区间外。
- 删除关注项先展示关联规则，确认后停用规则；历史事件保留标的快照。

“未查看/已查看”与“待发送/服务已接受/失败”分开记录。没有送达回执时，不展示“已送达手机”。

## 6. 持仓与数据口径

第一版限定美元计价的美股/ETF 多头持仓和非负美元现金。多个券商账户可分别录入，再汇总；其他币种先明确提示不支持，不能直接相加。

- 持仓字段：券商标签、账户别名、股票代码、数量、平均成本、币种、快照时间与录入来源。
- 现金字段：账户别名、币种、现金余额；不当作券商购买力或可提款金额。
- 导入以账户持仓快照为单位，预览替换范围并确认，不累计追加，避免重复导入翻倍。
- 持仓成本＝数量×平均成本；市值＝数量×有效报价；未实现盈亏＝市值－成本。
- 跨账户同一标的的平均成本＝合计成本÷合计数量；数量为零不参与计算。未实现盈亏比例＝未实现盈亏÷成本，成本为零则不可计算。
- 股票市值合计＋美元现金合计＝含现金总资产；计算使用 Decimal，并明确显示精度。
- 占比同时标注分母：股票持仓占比，或含现金总资产占比。
- 缺少报价时总资产标记“不完整”，不能静默按零估值；历史报价可展示但必须标注过期。
- 不提供已实现收益、税费归因、完整收益率曲线或账户日盈亏。标的日涨跌幅不等于账户日收益。
- 拆股、分红和成本变化由用户通过更新快照维护，v0.1 不自动重建交易账本。

## 7. 投资研究与 AI 能力边界

保留初始设计的 Investment Decision Context，作为关注模块内的手动信息，而非新增自动研究模块。

| 信息 | v0.1 支持方式 |
|---|---|
| 关注理由 / Investment Thesis | 用户编辑的文本，不由系统自动生成 |
| 投资期限 / Time Horizon | 用户填写的文本或日期说明 |
| 观察区间 / Watch Zone | 引用已配置的价格规则，不维护另一套重复阈值 |
| 风险备注 / Risk Notes | 用户维护风险与待核实事项 |
| 最近复核 / Last Reviewed | 用户明确执行复核动作时记录；不以行情刷新时间代替 |

这些信息随标的持久化，可从股票详情和提醒详情查看；字段可留空，不妨碍基础监控。真实备注、观察区间和持仓均属于私密运行数据。

v0.1 不调用在线 LLM、不自动总结财报或新闻、不生成买卖建议、不实现多 Agent 研究或订单草稿。保留独立的数据模型与服务接口，便于后续 AI Research 读取有来源和时间的上下文；仅保留扩展边界，不开发空壳 Agent 平台。

## 8. 交付范围与可选探索

| v0.1 必须完成 | 后续考虑 |
|---|---|
| 关注列表与有效性标记 | 更多市场、币种和自动汇率换算 |
| 手动/CSV 持仓和现金 | 长桥、IBKR 自动同步 |
| 确定性的价格规则与历史 | 基本面、新闻和组合风险规则 |
| 手动研究背景与复核日期 | AI 财报研究、新闻解读、自动投资建议 |
| 电脑和手机可用的网页 | PWA 主屏幕体验与网页推送 |
| 一个经过实机验证的手机通知渠道 | 多渠道回退和通知升级 |
| 服务健康状态和恢复验证 | 独立外部存活监测 |

不实现下单、改单、撤单接口。第一版不依赖在线 LLM，后续研究功能使用可追溯的数据上下文。

券商自动同步和替代行情源允许探索，但未通过独立验证前不显示为“已支持”。不能因可选接入不通而阻塞手动/CSV 路径，也不能为赶进度取消本版手机通知和持续监控的验收。

相对于最初构想，本版的收敛与补充如下：

| 设计项 | 本版口径 |
|---|---|
| 四个核心模块 | 保持不变；页面导航不改变模块边界 |
| macOS 本地通知 | 更新为手机通知闭环，优先微信；本地通知仅可用于调试 |
| 开发机本地运行 | 更新为 Air 开发、mini 独立监控，手机网页访问 |
| 券商自动同步 | 保留可选探索，不列为正式支持或发布前置条件 |
| 账户日盈亏与复杂现金指标 | 暂不支持；展示未实现盈亏与录入现金余额 |
| 盘前/盘后/夜盘 | 数据模型区分时段，本版提醒只覆盖正常交易时段 |
| 投资研究背景 | 保留手动字段与本地存储，AI 自动分析后置 |

## 9. 共同交付要求

- mini 后台任务独立于网页运行；Air 合盖后监控继续，任务互斥、状态持久化、失败有记录且有限重试。
- 报价过期、缺失或服务异常在网页显式展示；数据错误不得产生价格提醒。
- 手机在外网通过 HTTPS 和访问认证查看详情；未登录无法读取账户、规则或事件。
- 数据有一致性备份和恢复验证。mini 断电或整机断网时无法自发通知，不承诺永不中断。
- 代码、通用文档、模拟样例可上传 GitHub；真实数据、凭证、日志与私密研究背景遵循 [上传边界](REPOSITORY_POLICY.md)。

## 10. 验收标准

| 编号 | 通过条件 |
|---|---|
| AC-01 | 可增删、启停关注标的，报价/涨跌幅标明基准、来源和时间；真实源可获取演示列表标的报价；过期或非正常时段数据不会触发本版提醒 |
| AC-02 | 同一股票多个区间分别工作；边界、重叠、持续命中、离开重入、首次启用、冷却、启停和重启后的规则行为符合定义；旧事件保留规则快照 |
| AC-03 | 手动维护和 CSV 导入均可用；错误行阻止整批写入；重复导入不增加持仓；多账户汇总、加权成本、盈亏、现金和仓位占比以已知样例核对；不支持的币种或头寸明确拒绝 |
